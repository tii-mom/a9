# 04 — 单密钥托管与权限操作手册（含紧急暂停 / 技术终止演练）

**版本**：V7（时间参数）· 2026-11-05
**Owner**：testnet-ops
**决策依据**：docs/00（V7 时间参数；不设多签、单密钥 owner 最小权限、RC 不可升级、地址不公开）、docs/06 §8、docs/10 §9 风险登记册
**适用范围**：测试网全阶段；主网沿用同一套流程（参数与地址不同）

> **风险声明（必须知情）**：项目**不设多签、无时间锁、RoundController 不可升级**。单私钥丢失/泄露将导致对应资金损失或管理员能力被夺；营销/流动性/团队收款为**个人热钱包**且地址不公开，私钥泄露即直接损失。这些风险已由项目方书面接受（docs/00 §2.6、docs/10 §9），本手册只做缓解与演练，不改变风险归属。

## 1. 托管模型

~~~text
                      ┌─────────────────────────────┐
                      │ Owner 硬件钱包（单密钥）       │
                      │ 仅：开轮确认/关窗/暂停恢复/结算 │
                      └──────────────┬──────────────┘
                                     │ owner 消息
                      ┌──────────────▼──────────────┐
                      │ RoundController（不可升级）    │
                      │ 状态机/判定/claimAll/销毁指令  │
                      └───────┬──────────────┬──────┘
                              │ 仅 RC 指令     │ Jetton 转账/销毁
                    ┌─────────▼───────┐  ┌───▼────────────────────┐
                    │ TeamVault        │  │ 奖励/质押 Jetton Wallet │
                    │ 12 亿，只认 RC    │  │ owner = RoundController │
                    └─────────┬───────┘  └────────────────────────┘
                              │ 成功释放 1.2 亿 / 失败销毁 1.2 亿
                    ┌─────────▼───────┐
                    │ 团队收款热钱包     │  （地址不公开）
                    └─────────────────┘
~~~

- **管理员 = RoundController 单密钥 owner**，只能：开轮确认（含 R1 手动开轮）、SetJettonWallet（一次性）、关报名、暂停/恢复预言机、必要时触发结算、技术终止（任何人可触发，非特权）。
- **TeamVault 只接受 RC 指令**；非 RC 来源一律拒绝。
- **RC 不可升级**：无代理、无 setCode；规则只能通过新部署改变。
- **不允许取消质押**：唯一退款路径是 TECHNICAL_ABORTED（合约内条件触发，管理员不能手工退款）。

## 2. 密钥清单与保管

| # | 密钥/凭证 | 用途 | 存储 | 备份 | 轮换 |
| --- | --- | --- | --- | --- | --- |
| 1 | Owner 硬件钱包（RC admin） | 开轮确认/关窗/暂停恢复/结算 | Ledger/Trezor 离线；仅签名时连接 | 助记词离线 2~3 份、分离保管 | **不可轮换**（RC owner 固定）；丢失=失去管理能力，需重建部署 |
| 2 | TeamVault admin | 仅 InitController 一次 | 与 owner 同一硬件钱包或独立硬件钱包 | 同上 | InitController 后不再使用 |
| 3 | 部署者钱包（Acton 项目钱包） | 部署/注资/绑定 | 本地 keystore（acton wallet），助记词离线 | 离线备份 | 部署完成后可降级为低频冷钱包 |
| 4 | Treasury 冷钱包 | 持有初始 100 亿并分配 | 硬件钱包冷存储 | 离线多份 | 低频 |
| 5 | 团队收款热钱包 | 接收每轮 1.2 亿 | 个人热钱包；只留运营小额，大额转冷钱包 | 硬件钱包备份 | 建议每 3 个月或事件后轮换 |
| 6 | 营销热钱包（5 亿） | 营销支出 | 热钱包；小额 | 硬件钱包备份 | 每 3 个月/事件后 |
| 7 | 流动性热钱包（5 亿） | 加池/做市 | 热钱包；小额 | 硬件钱包备份 | 每季度 |
| 8 | 团队内盘管理钱包（公开） | 内盘未售/撤回代币 | 热钱包/多角色共管（无合约） | 硬件钱包备份 | 每季度；操作提前公告 |
| 9 | Keeper 提交密钥（测试网白名单） | 提交 K 线/tick | 服务器受限账户/环境变量 | 不备份历史值；轮换即换新 | 每季度或人员变动 |
| 10 | ADMIN_TOKEN（Worker） | admin API | wrangler secret；本地 .dev.vars 仅开发 | 密码管理器记录哈希/版本 | 每 90 天或泄露即换 |
| 11 | TONCENTER_API_KEY | 只读 RPC | 服务器环境变量 | 密码管理器 | 每 90 天 |
| 12 | Telegram Bot Token / Chat ID | 告警/公告 | 环境变量 | 密码管理器 | 泄露即 revoke |
| 13 | 预言机签名密钥（主网/二期） | K 线签名 | HSM/KMS（不可导出） | 按 KMS 策略 | 3/5 签名方独立轮换 |

**禁止**：
- 助记词/私钥写入仓库、脚本、config、聊天记录、云笔记、截图；
- 使用裸私钥（64 位 hex）代替助记词；
- 在联网浏览器输入硬件钱包助记词（恢复只在离线环境）；
- 共享屏幕/录屏时展示 keystore 或助记词；
- 把 owner 私钥放在部署服务器上（owner 只在硬件钱包签名）。

## 3. 硬件钱包与冷热分离

1. **购买渠道**：只从官方渠道购买，检查防拆封；初始设置时自行生成助记词（不接受预生成）。
2. **固件**：仅官方固件，开启 PIN，关闭蓝牙/U 盘模式（如不需要）。
3. **签名审查**：每笔交易在设备屏幕上核对：目标合约地址、opcode/金额、链（testnet 标识）、gas；地址逐段核对（首尾 + 中间）；不确定即拒绝。
4. **双人在场**：owner 写操作时第二人核对屏幕与登记表；操作后共同签字。
5. **冷热分离**：owner/treasury 冷；运营热钱包只留小额；热钱包余额超阈值即转冷。
6. **环境隔离**：签名用专用电脑（最小软件安装、全盘加密、自动更新）；不安装浏览器扩展钱包（除测试需要）。

## 4. 备份规范（3-2-1-1）

- **3 份**：至少 3 份助记词备份（原始 + 2 份副本）。
- **2 种介质**：如金属助记词板 + 密封纸质（或加密硬件备份）。
- **1 份异地**：地理分离（不同城市/保险柜）。
- **1 份离线**：永不联网；不与私钥同库存放。
- **可选 SLIP-39 分片**：2/3 或 3/5 分片，分给不同负责人；不要一人持有全部分片。
- **登记**：备份位置、保管人、封装编号、最后一次校验时间写入密钥台账（不写助记词本身）。
- **校验**：每季度在**离线/测试网**环境用备份恢复一个测试钱包（只验证助记词有效，不导入真实资产）；每年至少一次完整恢复演练。
- **恢复演练记录**：时间、参与人、结果、问题、改进（归档 ops/drills/）。

## 5. 权限边界（硬约束）

### 5.1 Owner 允许

| 操作 | 条件 | 说明 |
| --- | --- | --- |
| OpenRound | 上一轮已终态；R1 无 PREVIEW 必须 admin 手动开（R2~R10 自动） | 开窗交易锁定 target；R1 交易带 twap24h |
| SetJettonWallet（0x52540016） | RC/TV 部署后、InitController 前，一次性 | admin 写入 canonical Jetton Wallet；之后不可改 |
| CloseStaking | 报名窗口内/触价 | 正常到点自动关；手动仅兜底 |
| PauseOracle / ResumeOracle | 数据故障/恢复 | 暂停不判负、不销毁 |
| FinalizeRound | 24 根齐备/条件满足 | 必要时触发；正常任何人可触发 |
| AbortTechnical | 连续暂停 14 天或观察超时 7 天 | 任何人可触发；owner 不独占 |

### 5.2 绝对禁止（合约层拒绝或不应存在）

| 禁止操作 | 依据 |
| --- | --- |
| 修改已开轮目标价 / K 线阈值 / oracle config hash | D-24、docs/02 |
| 转移用户质押本金 / 手工退款 | D-24；唯一退款路径 AbortTechnical |
| 取消质押 / 提前退出 | V5.3；无 CancelStake 消息 |
| 升级 / 替换 RC 代码 | D-24；无代理 |
| 把 SUCCEEDED / FAILED_PERMANENT 改回活动状态 | docs/02 §1 终态不可逆 |
| 绕过 TeamVault 直接动用团队额度 | TeamVault 只认 RC |
| 提前触发技术终止 / 伪造暂停条件 | V6.1；条件不满足会 revert |

### 5.3 双人复核清单（每次 owner 写操作）

- [ ] 操作类型与轮次正确（防错轮/错动作）；
- [ ] 目标合约地址与登记表一致（逐段核对）；
- [ ] 参数（roundId、reason、金额）与公告/工单一致；
- [ ] 设备屏幕显示与预期一致（链、合约、方法、金额）；
- [ ] 第二人独立核对并签字；
- [ ] 操作后立即核对链上事件与状态；
- [ ] 记录：时间、操作者、复核者、交易哈希、结果、截图。

## 6. 管理员操作 SOP

### 6.1 只读巡检（随时）

~~~bash
node ops/scripts/80_admin_ops.mjs --action status --round <N>
node ops/scripts/monitor_check.mjs
~~~

### 6.2 暂停预言机（P1 场景）

1. 触发条件：数据缺失/来源不足/时间戳异常/签名失败/合约异常（docs/03 §10）。
2. 双人确认；检查当前轮次为 OBSERVING。
3. 执行：

~~~bash
node ops/scripts/80_admin_ops.mjs --action pause-oracle --round <N> --reason <code>
~~~

   真实执行：OPS_EXECUTE=1 OPS_CONFIRM=YES。

4. 核对：轮次状态 ORACLE_PAUSED；记录 pausedAt、最后有效 K 线、原因。
5. 发布 pause 公告（05 手册）；启动 14 天计时。
6. 恢复：确认数据源稳定后 resume-oracle；恢复后重收 24 根（1h K 线）；发 resume 公告。

### 6.3 关窗 / 结算

- 正常到点自动关窗/结算；仅在逾期或 keeper 故障时由 owner 兜底，且必须先确认窗口/24 根数据条件。
- 失败结算必须确认三笔 burn 全部 BurnAck 后才可对外公告；不得手工把状态改为 FAILED_PERMANENT。

### 6.4 开轮（R1 必须手动，R2~R10 自动）

- R1（contracts/README §3.2）：无 PREVIEW，部署完成后由 admin 手动 OpenRound，交易中传 twap24h，stakeOpenAt = now。
- R2~R10：PREVIEW 结束自动开窗；测试网人工只做确认与公告，不提前/延后。
- 开轮前检查：SetJettonWallet 已完成、InitController 已绑定、RC ≥20 TON、TV ≥10 TON、奖励/团队已注资、公告已发。
- 双人核对，记录 target 与 TWAP，开轮后核对 TargetPriceSet 事件。

## 7. 紧急暂停 SOP（Emergency Pause）

**适用**：疑似漏洞、异常价格/数据、异常管理员操作、供应量漂移、密钥泄露迹象。

**目标时限**：发现后 15 分钟内完成暂停（若暂停可缓解）+ 首次公告。

1. **拉群（≤2 分钟）**：On-call + Ops Lead + 合约负责人；明确事故编号。
2. **判断（≤5 分钟）**：是否影响本金/奖励/销毁/团队额度；是否仍在观察/报名窗口。
3. **执行暂停（≤10 分钟）**：
   - 若在观察期且为数据类问题：pause-oracle（双人）。
   - 若为合约/资金类问题且无法暂停：停止前端质押入口（运维开关/公告）、停止 keeper 提交、保留现场。
   - 若是密钥泄露：见 §9，先冻结相关热钱包余额（转冷/撤销授权），评估 owner 是否需放弃管理能力。
4. **核对（≤15 分钟）**：链上状态、最后交易、K 线/质押快照；截图与哈希归档。
5. **公告（≤30 分钟）**：pause 模板；说明“已暂停、不判负、不销毁、退款条件”，不猜测原因/不承诺时间。
6. **止损与定位**：隔离数据源/keeper；对比对账；与审计/合约负责人评估。
7. **恢复**：满足条件后 resume；重收 24 根；发 resume 公告；复盘。
8. **如果暂停无法缓解资金风险**：进入技术终止评估（§8）或紧急公告 + 前端下线；不得隐瞒。

**禁止**：暂停期间结算/销毁；用暂停掩盖市场失败；未经双人确认操作。

## 8. 技术终止演练（TECHNICAL_ABORTED）

### 8.1 触发条件（合约硬条件，不满足会 revert）

- 连续暂停 **14 天**（techAbortPauseSeconds = 1,209,600 秒）；或
- 观察结束超时 **7 天**（techAbortObsTimeoutSeconds = 604,800 秒）。
- **任何人**可触发；不消耗档位；退还 100% 本金；不销毁奖励/团队额度；不标记市场失败。

### 8.2 演练步骤（测试网）

> 测试网主参数固定 14 天/7 天，无法压缩。**演练方式**：(A) 用独立的短参数测试部署（例如 pauseSeconds=600）跑完整流程；或 (B) 在主部署上真实等待（不推荐占用 10 轮排期）。演练必须在 ops/drills/ 留记录。

1. **准备**：确认测试轮有质押（至少 2 个地址）、本金快照、档位快照；记录 total_supply。
2. **制造暂停**：owner 执行 pause-oracle（双人），记录 pausedAt。
3. **等待条件**：短参数部署等待 10 分钟；主部署需 14 天。监控 14 天计时与告警。
4. **触发终止**（任何人，可用 keeper 地址）：

~~~bash
node ops/scripts/80_admin_ops.mjs --action abort-technical --round <N>
~~~

5. **核对**（逐项）：
   - [ ] 轮次状态 TECHNICAL_ABORTED；
   - [ ] 每个质押地址本金 100% 可退/已退（金额 = 其 stake）；
   - [ ] 奖励额度**未**销毁（奖励池余额不变）；
   - [ ] 团队额度**未**销毁（TeamVault 余额不变）；
   - [ ] tier 不变（不消耗档位）；
   - [ ] total_supply 未因本轮减少（除正常其他轮次）；
   - [ ] 事件 TechnicalAborted 已发出。
6. **公告**：abort 模板；说明原因、退款、不销毁、档位不变。
7. **下一轮**：按原 tier 继续；确认 PREVIEW/开窗正常。
8. **复盘**：计时（发现→暂停→终止→退款→公告），记录问题与改进。

### 8.3 演练验收标准

| 项 | 标准 | 记录 |
| --- | --- | --- |
| 触发权限 | 任意地址可触发；owner 不独占 | 交易发送者地址 |
| 退款 | 100% 本金，逐地址核对 | 对账 CSV + 交易哈希 |
| 不销毁 | 奖励池/TeamVault 余额不变 | 余额截图 + 交易 |
| 档位 | tier 不变 | get_round targetTier |
| 无市场失败标记 | 状态为 TECHNICAL_ABORTED 而非 FAILED_PERMANENT | 链上状态 |
| 时间 | 发现→暂停 ≤15 分钟；暂停→终止按参数；终止→退款 ≤1 小时 | 计时表 |

## 9. 密钥事件响应

### 9.1 私钥泄露 / 被盗

1. **立即**：停止一切写操作；把相关热钱包余额转移到新地址（若私钥仅控制热钱包）；撤销授权/停止 keeper。
2. **评估**：泄露的是 owner、TeamVault admin、部署者、热钱包、还是 API key？
   - owner 泄露：攻击者可开轮/关窗/暂停/结算，但不能转移本金、不能改目标价、不能升级；立即公告、暂停前端、联系合约负责人评估重建；必要时技术终止受害轮次。
   - TeamVault admin 泄露：仅在未 InitController 时可被抢先绑定；已绑定则无法改变 controller；监控异常 InitController 尝试。
   - 热钱包泄露：直接资金损失，立即转移剩余余额并公告。
   - API key/Token：立即 revoke/rotate（wrangler secret、TG bot、TON Center）。
3. **取证**：保留交易哈希、日志、设备状态；不要清理现场。
4. **公告**：说明影响范围、已采取措施、用户需做什么（如停止质押），不隐瞒。
5. **复盘 + 重建**：评估是否需要新部署（RC 不可升级是硬约束）；更新密钥台账与流程。

### 9.2 私钥丢失

- owner 丢失 = 失去管理能力（无法开轮/暂停/结算），但用户本金仍在合约内、技术终止仍可由任何人触发；需重建部署并公告。
- 热钱包丢失 = 直接损失该地址余额；用备份恢复或转移剩余。
- **备份恢复演练**是唯一可靠缓解；没有演练过的备份视为不可用。

## 10. 轮换演练（每季度）

| 对象 | 步骤 | 验证 |
| --- | --- | --- |
| 热钱包（团队/营销/流动性） | 生成新钱包 → 备份 → 小额测试转账 → 转移余额 → 更新登记表 → 公告 | 新旧余额、登记表、对账 |
| ADMIN_TOKEN | wrangler secret put 新值 → 更新值班工具 → 验证旧 token 401 → 记录 | /api/admin 401/200 |
| TONCENTER_API_KEY | 新 key → 环境变量替换 → 旧 key revoke | 查询成功、旧 key 失败 |
| Keeper 密钥 | 新地址加入白名单 → 切换 → 旧地址移除 | 提交成功/失败 |
| Owner（不可轮换） | 说明：RC owner 固定，无 setOwner；变更只能新部署 | 记录“不可轮换”结论 |
| 备份（助记词） | 离线恢复测试钱包 → 校验地址 → 重新封装 | 地址一致、封装完好 |

每次轮换记录：时间、对象、操作者、复核者、验证结果、旧凭证处置方式。

---

## 11. 审计日志与留存

- 链上：所有 owner 操作、TeamVault 指令、burn/claim 事件 → 交易哈希归档。
- 链下：admin_events（D1）、部署脚本输出、监控告警、双人复核签字、公告链接。
- 留存：至少到主网后 90 天；密钥台账长期（不含密钥本身）。
- 每月抽查 10 条管理员操作：是否双人、是否有工单、是否与公告一致。

## 12. 定期检查清单

### 每月

- [ ] 硬件钱包固件/设备状态；PIN 与助记词封装完好。
