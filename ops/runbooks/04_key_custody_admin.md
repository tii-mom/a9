# 04 — 密钥托管与 keeper 操作手册（测试网，v10）

**版本**：v10（2026-11-06，D-42）
**Owner**：testnet-ops
**决策依据**：docs/00 的 D-42（单 keeper 热钱包、无 admin、RC 不可升级）、contracts/README §0 与 §3
**适用范围**：测试网全阶段；主网沿用同一套流程，参数与地址不同（主网见 06）

> **风险声明（必须知情）**：v10 **没有 admin，没有升级，没有提现**。运营只有一个 keeper 热钱包，它能开轮、提交 K 线。keeper 私钥泄露后，攻击者可以伪造 K 线，决定任意一轮的成败；合约无法阻止，也无法更换 keeper（部署时写入，之后不可改）。这一风险已由项目方书面接受（docs/00 D-42）。本手册只做缓解与演练，不改变风险归属。

---

## 1. 托管模型

~~~text
keeper 热钱包（只放 gas）
   │ OpenRound / SubmitCandle（只有它能发）
   │ CloseStaking / AbortTechnical / RetrySettlement（任何人可发）
   ▼
RoundController（不可升级、无提现、无 admin）
   │ Jetton 转账 / 销毁
   ▼
RC 的 Jetton 钱包（82 亿 A9：70 亿奖励池 + 12 亿团队额度）
   ├─ 成功轮：1.2 亿 → teamWallet（RC 直接转）
   ├─ 用户领取：本金 + 奖励
   └─ 失败轮：一笔销毁（7 亿 + 1.2 亿 + 全部本金）

treasury（mint 100 亿）→ 82 亿 RC；8 亿内盘、5 亿流动性、5 亿营销（注资后归零）
~~~

- **keeper 是唯一的运营写权限**，且只能做开轮与提交 K 线。它不能改参数，不能转走资金，不能暂停。
- **RC 不可升级**：没有代理、没有 setCode、没有 setAdmin。规则只能通过新部署改变。
- **不允许取消质押**：唯一的退款路径是无效质押退回与技术终止后的本金领取（合约内规则）。运营没有手工退款入口。

## 2. 密钥清单与保管

| # | 密钥或凭证 | 用途 | 存储 | 备份 | 轮换 |
| --- | --- | --- | --- | --- | --- |
| 1 | keeper 热钱包 | OpenRound、SubmitCandle；只放 gas | 服务器受限账户（acton keystore 或环境变量） | 不备份历史值；助记词离线 ≥ 2 份 | **不可轮换**：地址在部署时写入 RC；泄露 = 只能重新部署（见 §9.1） |
| 2 | 部署者钱包（Acton 项目钱包） | 部署、注资、运维期 gas | 本地 keystore；助记词离线 | 离线备份 | 部署完成后降级为低频钱包，余额转出 |
| 3 | treasury | 持有 mint 的 100 亿并分配 | 测试网可用热钱包；主网用冷钱包（见 06） | 离线备份 | 注资完成后余额归零 |
| 4 | teamWallet | 每成功轮接收 1.2 亿 | 热钱包，只留运营小额；大额转冷钱包 | 硬件钱包备份 | **不可轮换**：地址在部署时写入 RC；只能转移余额（见 §9.2） |
| 5 | marketingWallet（5 亿） | 营销支出 | 热钱包，小额 | 硬件钱包备份 | 每 3 个月或事件后 |
| 6 | liquidityWallet（5 亿） | 加池与做市 | 热钱包，小额 | 硬件钱包备份 | 每季度 |
| 7 | teamInternalWallet（8 亿，公开） | 内盘未售与撤回代币 | 多人共管热钱包（无合约） | 硬件钱包备份 | 每季度；操作提前公告 |
| 8 | ADMIN_TOKEN（Worker） | Worker 管理接口 | wrangler secret；本地 .dev.vars 仅开发用 | 密码管理器记录版本 | 每 90 天或泄露即换 |
| 9 | TONCENTER_API_KEY | 只读 RPC | 服务器环境变量 | 密码管理器 | 每 90 天 |
| 10 | Telegram Bot Token / Chat ID | 告警与公告 | 环境变量 | 密码管理器 | 泄露即 revoke |

**注意**：teamWallet 与 keeper 地址写在 RC 里，无法在链上更换。测试网如果需要更换，只能整套重新部署（见 01 §9）。

**禁止**：

- 助记词或私钥写入仓库、脚本、配置、聊天记录、云笔记、截图；
- 使用裸私钥（64 位 hex）代替助记词；
- 在联网浏览器输入硬件钱包的助记词（恢复只在离线环境进行）；
- 共享屏幕或录屏时展示 keystore 或助记词；
- 把 keeper 私钥放在与公开服务同一台机器上（见 §4）。

## 3. 热钱包与冷热分离

1. **keeper**：只放运行所需的 gas（约 2 TON 起，见 monitor.keeper.ton_low）；不放任何 A9。
2. **资金钱包**（treasury、teamWallet、marketing、liquidity、teamInternal）：只放运营所需的小额；大额转冷钱包。
3. **签名审查**：每笔交易确认目标地址、opcode、金额与链（testnet 标识）。地址首尾与中间都要核对；不确定就拒绝。
4. **双人在场**：任何 keeper 的手工写操作（见 02 §2），第二人核对地址与参数，操作后共同签字。
5. **环境隔离**：签名环境只装必要软件、全盘加密、自动更新。浏览器钱包扩展仅用于测试需要。

## 4. 备份规范（3-2-1-1）

- **3 份**：至少 3 份助记词备份（原件 + 2 份副本）。
- **2 种介质**：例如金属助记词板加密封纸质，或加密硬件备份。
- **1 份异地**：地理分离（不同城市或保险柜）。
- **1 份离线**：永不联网，不与私钥同库存放。
- **可选 SLIP-39 分片**：2/3 或 3/5 分片分给不同负责人；不要一人持有全部分片。
- **登记**：备份位置、保管人、封装编号、最后一次校验时间写入密钥台账（不写助记词本身）。
- **校验**：每季度在离线或测试网环境用备份恢复一个测试钱包（只验证助记词有效，不导入真实资产）；每年至少一次完整恢复演练。
- **演练记录**：时间、参与人、结果、问题、改进；归档到 ops/drills/。

## 5. 权限边界与双人规则

### 5.1 keeper 允许

| 操作 | 条件 | 说明 |
| --- | --- | --- |
| OpenRound（0x52540001） | 上一轮已判定（或 R1）；预告结束后 | 开窗并锁定 target；R1 交易携带 twap24h |
| SubmitCandle（0x52540003） | 观察期内，每小时一根 | 第 24 根提交即判定 |

### 5.2 任何人允许（不是 keeper 特权）

| 操作 | 条件 | 说明 |
| --- | --- | --- |
| CloseStaking（0x52540002） | 报名 36h 到期后 | 正常由 keeper 调用；值班人员可兜底 |
| AbortTechnical（0x52540010） | 观察应结束或预告结束后 7 天 | 条件不满足时 revert |
| RetrySettlement（0x52540015） | 出现 SettlementBounced，value ≥ 0.3 TON | 只针对事件中的 roundId |

### 5.3 绝对禁止（合约层不允许，或不应存在）

| 禁止操作 | 依据 |
| --- | --- |
| 修改已开轮的目标价，或 K 线参数 | 合约规则（D-42） |
| 转移用户本金，或手工退款 | 合约无此入口 |
| 取消质押，或提前退出 | 无 CancelStake 消息 |
| 升级 RC、替换 RC 代码、更换 keeper | 不可升级，无 admin |
| 把已判定轮次改回活动状态 | 终态不可逆 |
| 提前触发技术终止，或伪造条件 | 条件不满足会 revert |
| 手工转账“补救”结算 | 只能用 RetrySettlement |

### 5.4 双人复核清单（每次 keeper 手工写操作）

- [ ] 操作类型与轮次正确（防止错轮、错动作）；
- [ ] 目标合约地址与登记表一致（逐段核对）；
- [ ] 参数（roundId、candleIndex、twap、digest）与公告或工单一致；
- [ ] 签名环境显示的链与合约一致；
- [ ] 第二人独立核对并签字；
- [ ] 操作后立即核对链上事件与状态；
- [ ] 记录：时间、操作者、复核者、交易哈希、结果。

## 6. keeper 操作 SOP

### 6.1 只读巡检（随时）

~~~bash
node ops/scripts/80_admin_ops.mjs --action status --round <N>
node ops/scripts/monitor_check.mjs
~~~

### 6.2 开轮（OpenRound）

- 时点：预告期结束（T0 + 12h），R1 为部署后。
- 开轮前检查：上一轮已判定；RC TON ≥ 20；keeper TON ≥ 2；公告已发；R1 的 twap24h 已双人复核（见 07 §9.1）。
- 执行：
  ~~~bash
  OPS_EXECUTE=1 OPS_CONFIRM=YES A9_SIGNER_WALLET=<keeper> node ops/scripts/80_admin_ops.mjs --action open-round --round <N> --twap24h <USD_E8>
  ~~~
- 核对：TargetPriceSet 事件；`get_round(N)` 的 target 与公告一致。

### 6.3 关窗（CloseStaking）

- 报名 36h 到期后执行。keeper 正常执行；值班人员可在 1 小时内兜底。
- 执行：
  ~~~bash
  OPS_EXECUTE=1 OPS_CONFIRM=YES A9_SIGNER_WALLET=<wallet> node ops/scripts/80_admin_ops.mjs --action close-staking --round <N>
  ~~~
- 核对：StakingClosed 事件；状态变为 OBSERVING。

### 6.4 提交 K 线（SubmitCandle）

- 每小时一根，共 24 根；periodStart = observationStart + i × 3600。
- 执行与校验规则见 02 §3.5。
- 数据来源保留原始记录，供公开复核。

### 6.5 结算重试（RetrySettlement）

- 只在 SettlementBounced 出现后执行，并按 02 §3.6.1 留痕。

## 7. keeper 失联应急

1. **确认**：keeper 服务是否停止；TON 是否耗尽；最近一次 OpenRound 或 SubmitCandle 的时间。
2. **恢复**：若服务问题，在隔离环境恢复；补充 gas；按 02 §3.5 补交缺失的 K 线（只能按正确时间戳补交）。
3. **不能做的事**：不能更换 keeper（合约内无此入口）；不能手工改结果；不能用其他钱包冒充 keeper。
4. **兜底**：
   - 观察应结束后 7 天仍未判定，或预告结束后 7 天仍未开轮，任何人可调用 AbortTechnical，本金可领取，轮次不消耗档位。
   - 在这 7 天内，若 keeper 仍能恢复，按正常流程继续。
5. **公告**：keeper 中断超过 1 小时时发状态更新；不猜测原因，不承诺恢复时间。

## 8. 技术终止演练（TECHNICAL_ABORTED）

### 8.1 触发条件（合约硬条件，不满足会 revert）

- 观察应结束后 **7 天**仍未判定；或
- 预告结束后 **7 天**仍未开轮（keeper 失联）。
- **任何人**可调用；不消耗档位；本金 100% 可领取；7 亿奖励与 1.2 亿团队额度留在 RC，不分配、不销毁。

### 8.2 演练步骤（测试网）

> 7 天窗口在主测试网无法压缩。**演练方式**：(A) 用独立的短参数测试部署完整跑一遍（是否支持短参数，需合约负责人确认）；(B) 在主部署上真实等待（不推荐，会占用 10 轮排期）。演练必须在 ops/drills/ 留记录。

1. **准备**：记录测试轮的质押地址（至少 2 个）、本金快照、档位、total_supply 与 RC 钱包余额。
2. **制造条件**：让 keeper 停止开轮（或停止提交 K 线），记录最后一次成功操作的时间。
3. **等待**：满足 7 天条件（或短参数部署下的等价时长）；监控计时。
4. **触发**（任何人，可用非 keeper 地址）：
   ~~~bash
   OPS_EXECUTE=1 OPS_CONFIRM=YES A9_SIGNER_WALLET=<wallet> node ops/scripts/80_admin_ops.mjs --action abort-technical --round <N>
   ~~~
5. **核对**（逐项）：
   - [ ] 轮次状态为 TECHNICAL_ABORTED（10）；
   - [ ] 每个质押地址本金 100% 可领取（金额 = 其质押额）；
   - [ ] 7 亿奖励未销毁，RC 钱包余额中仍然保留；
   - [ ] 1.2 亿团队额度未转出，也未销毁；
   - [ ] tier 不变；
   - [ ] total_supply 未因本轮减少；
   - [ ] TechnicalAborted 事件已发出（reason 为观察超时或预告超时）。
6. **公告**：abort 模板；说明原因、本金可领取、不销毁、档位不变。
7. **下一轮**：按原 tier 继续；确认预告与开轮正常。
8. **复盘**：计时（发现 → 条件满足 → 终止 → 领取），记录问题与改进。

### 8.3 演练验收标准

| 项 | 标准 | 记录 |
| --- | --- | --- |
| 触发权限 | 任意地址可调用；keeper 不独占 | 交易发送者地址 |
| 本金领取 | 每个地址 100% 可领取，逐个核对 | 对账 CSV + 交易哈希 |
| 不销毁 | 7 亿与 1.2 亿留在 RC，未分配 | RC 钱包余额前后对比 |
| 档位 | tier 不变 | get_round 的 tier |
| 状态 | TECHNICAL_ABORTED，而非 FAILED_PERMANENT | 链上状态 |
| 时间 | 条件满足 → 终止调用 ≤ 1 小时 | 计时表 |

## 9. 密钥事件响应

### 9.1 keeper 私钥泄露或被盗

1. **立即**：停止 keeper 服务；把 keeper 余额转到新地址（只限剩余 gas）；停止前端质押入口（运维开关）。
2. **认清限制**：keeper 不能更换。攻击者仍可以用这把钥匙开轮和提交 K 线，直到合约本身的规则生效。停止服务并不能阻止攻击者继续出手。
3. **评估**：哪些轮次可能受影响（攻击者可以在观察期提交伪造 K 线，决定一轮成败，并让自己的质押轮次成功）。公开数据复核，列出疑似受影响的轮次。
4. **取证**：保留交易哈希、日志、服务器状态；不要清理现场。
5. **公告**：说明影响范围、已采取措施、用户需要做什么（例如暂停质押），不隐瞒。
6. **复盘与重建**：评估重新部署（RC 不可升级、无更换入口，这是唯一的补救路径）；更新密钥台账与流程。

### 9.2 其他钱包泄露

- **teamWallet / marketing / liquidity / teamInternal**：这些是普通钱包，没有合约权限。立即转移剩余余额到新地址，并更新登记表（注意 teamWallet 地址已写在 RC 中，不能更改，只能转移资金，或在主网前整套重建）。
- **ADMIN_TOKEN 或 API key**：立即 revoke 或 rotate（wrangler secret、Telegram Bot、TON Center）。

### 9.3 私钥丢失

- **keeper 丢失**：无法开轮和提交 K 线。轮次会因 7 天条件进入技术终止，本金可领取，但协议无法继续运营，需要重新部署。
- **资金钱包丢失**：直接损失该地址余额。用备份恢复，或在丢失前转移。
- **备份恢复演练**是唯一可靠的缓解方式。没有演练过的备份视为不可用。

## 10. 轮换演练（每季度）

| 对象 | 步骤 | 验证 |
| --- | --- | --- |
| 资金钱包（marketing / liquidity / teamInternal） | 生成新钱包 → 备份 → 小额测试转账 → 转移余额 → 更新登记表 → 公告 | 新旧余额、登记表、对账 |
| teamWallet | **不可在链上更换**。只能转移资金；若需更换，属于整套重建，不在本演练范围 | 记录结论 |
| keeper | **不可在链上更换**。只能停止并重新部署；本演练只做备份恢复验证 | 记录结论 |
| ADMIN_TOKEN | wrangler secret put 新值 → 更新值班工具 → 旧 token 失效验证 → 记录 | 管理接口旧 token 拒绝、新 token 通过 |
| TONCENTER_API_KEY | 新 key → 环境变量替换 → 旧 key revoke | 查询成功，旧 key 失败 |
| 助记词备份 | 离线恢复测试钱包 → 校验地址 → 重新封装 | 地址一致，封装完好 |

每次轮换记录：时间、对象、操作者、复核者、验证结果、旧凭证处置方式。

## 11. 审计日志与留存

- **链上**：keeper 的所有交易、CloseStaking、AbortTechnical、RetrySettlement，以及相关事件，归档交易哈希。
- **链下**：管理事件、部署输出、监控告警、双人复核签字、公告链接。
- **keeper 出账**：每一笔出账都要有对应的预期操作（OpenRound 或 SubmitCandle）；异常出账立即告警。
- **留存**：至少到主网后 90 天；密钥台账长期保存（不含密钥本身）。
- **抽查**：每月抽查 10 条 keeper 操作，核对是否双人、是否有工单、是否与公告一致。

## 12. 定期检查清单

### 每月

- [ ] 硬件钱包固件与设备状态；PIN 与助记词封装完好。
- [ ] 资金钱包余额是否超过运营阈值；大额是否已转冷。
- [ ] keeper 出账记录与预期操作对账。
- [ ] ADMIN_TOKEN、API key 是否临近轮换期。
- [ ] 备份位置、保管人是否变更。

### 每季度

- [ ] 完整备份恢复演练（测试网或离线环境）。
- [ ] 资金钱包轮换演练。
- [ ] keeper 失联应急演练（计时）。
- [ ] 权限边界复核：是否出现新的写入口或新脚本。
- [ ] 密钥台账与登记表一致性复核。

### 每半年

- [ ] 技术终止完整演练（短参数部署或主部署条件满足）。
- [ ] 灾难恢复推演：keeper 泄露、合约漏洞、供应量漂移。
- [ ] 与审计方或交易所披露的地址清单复核（不公开地址）。
