## 2. 关键技术原则

1.  用户质押资产必须实际转入协议控制的 Jetton
    Wallet；不得假设合约可以从用户个人钱包强制扣款。
2.  价格数据必须来自可验证的预言机/签名数据源；普通网页 API
    或单一后台数据库不能直接作为链上最终裁决依据。
3.  TON
    合约间通过异步消息交互。质押入账、返还、销毁和奖励支付必须采用可重试、幂等的多阶段结算。
4.  失败销毁必须是实际 Jetton burn，并确认 Jetton Master 的 total_supply
    已减少；不能仅把余额记为"不可用"就宣称已销毁。
5.  合约不得遍历全体用户进行批量派发。采用用户主动领取（pull
    claim）模式。
6.  任何预言机故障、数据缺失或合约技术故障，不得伪装成价格考核失败并销毁本金。
7.  用户质押前必须明确确认"本轮失败时，本轮全部质押本金可能100%销毁"。

## 6. 核心风险提示

本协议具有极高风险：市场考核失败将导致参与该轮的用户损失全部质押本金。价格翻倍阶梯也意味着第10轮目标为初始参考价的1024倍（P0 = $0.00116 → R10 = $1.18784）。该机制不保证价格上涨、不保证奖励实现，也不能保证防止抛售或操纵。

项目**不设多签**：营销 5%、流动性 5%（5 亿 A9）与团队收款钱包均为**个人热钱包且地址不公开**，团队额度由 TeamVault 托管、按轮次释放/销毁，管理员为单密钥 owner；私钥丢失或泄露将直接造成资金损失或权限丧失，该风险已由项目方接受（缓解要求见 docs/06 §8、docs/10 §9）。
**经济模型风险**：docs/13 的蒙特卡洛显示，在常见波动率下「48h 内翻倍」通过率接近 0；项目方已最终确认 2×（D-31），因此该风险被视为已知风险保留，缓解依赖 D-26（B+ 闸门）、D-28（同档重试）、D-29（R1 启动规则）等待确认项；未定案前不宜上主网。
另外，**报名窗口 72h 下若现价已明显高于该轮目标价，观察期几乎确定通过**，参与者可在报名时锁定「无风险白拿 7 亿」，奖励会被逐轮抛售。该问题已列为 V5 最高优先级待决策（docs/00 §7），未定案前不得进入主网参数设计。

本文件不能替代法律意见、经济模型审查、智能合约审计或市场操纵风险评估。
