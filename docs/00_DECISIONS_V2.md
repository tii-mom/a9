### 2.2 价格阶梯

- **V6 定稿公式**：`target = max(阶梯 P0 × 2^tier, 2 × 开窗时 24h TWAP)`，在**开窗时锁定**，锁定后本轮不可改。
  - 阶梯提供下限（`P0 × 2^tier`），24h TWAP 提供「相对当前价翻倍」的下限逻辑：若价格已高于阶梯，则目标随之上移，避免「报名期已达标白拿」。
  - **V6 已取消**：95% 开窗价格闸门、7 天等待与提档（因为目标在**看到开窗价之后**才锁定，不需要闸门）。
  - **保留**：触价提前关窗——报名期内 1h TWAP ≥ 目标 → 立即关窗进入观察。

### 2.3 每轮机制（V6 时间线）

1. **结算 → 24h 预告期（PREVIEW）**：本轮结算（成功/失败、团队释放/销毁、进入领取）后，进入**固定 24 小时预告期**；前端展示倒计时与分享卡片；预告期结束时**自动开窗**（无需价格闸门）。
2. **报名（72 小时）**：用户把 A9 转入质押金库，payload 写入风险确认（roundId / nonce / riskDisclosureVersion / acceptFullPrincipalBurn=true）。窗口 72 小时；**报名期内 1h TWAP ≥ 目标 → 立即提前关窗**；到点正常关闭。
3. **观察（72 小时）**：关窗后开始 **18 根连续 4 小时 K 线**，每根用多源 TWAP（**≥12 根 ≥ 目标价即通过**，等于也算；容错 6 根）。
4. **判定**：18 根齐备后，`qualified >= 12` 成功、`<= 11` 失败，**无中间态**；随后进入成功/失败结算与下一轮预告。
5. **单轮 7 天，10 轮 70 天**（24h 预告 + 72h 报名 + 72h 观察 = 168h = 7 天/轮）。
6. **成功**：本金退还 + **7 亿奖励按质押比例认领**（pull claim，可跨轮累积一次性领取）+ **团队 1.2 亿由 TeamVault 立即转出到团队收款钱包**（无 cliff、无线性）。
7. **失败**：三笔销毁 —— 本轮 **7 亿奖励 + 团队轮次额度 1.2 亿 + 本轮全部质押本金**；供应量减少，失败轮永久关闭。
8. **无人质押**：本轮照常启动并进入观察（不卡轮次、不判负）。
   - 失败：照常销毁本轮奖励（无本金可销毁）。
   - 通过：本轮奖励按质押比例分给所有质押人；即使只有 1 人，该人拿走本轮全部奖励。
   - 0 人质押且通过：奖励无接收人 → **本轮 7 亿奖励销毁**（D-18b 已确认：不回流、不留存、不补发）。

### 2.5 团队额度与 TeamVault（V5）

团队 12% = 1,200,000,000 由**独立 TeamVault 合约**托管，与轮次**完全同步**：

``` text
TEAM_ROUND_RAW = 1,200,000,000 / 10 = 120,000,000（1.2 亿）
托管：TeamVault 持有 12 亿对应的 Jetton Wallet（owner = TeamVault 合约）

  本轮 SUCCEEDED        → TeamVault 转 1.2 亿到团队收款钱包（无 cliff / 无线性）
  本轮 FAILED_PERMANENT → TeamVault 销毁 1.2 亿（burn_ledger kind = "team"）
```

- **TeamVault 只接受 RoundController 的指令**；其他来源的消息一律拒绝。

- 团队收款钱包地址在**部署前填入 config**（热钱包，见 §2.6）。
- 不部署 Lockup / Vesting 合约，团队没有独立归属曲线；原「12 个月 cliff + 36 个月线性」描述**作废**。
- 供应量：成功轮不减少供应（额度转为流通）；失败轮 total_supply 实际减少 1.2 亿。

### 2.6 托管与权限（V5：不设多签，单密钥最小权限）

- **不设多签**；营销 5%（5 亿）与流动性 5%（5 亿）由**个人热钱包**持有；团队收款钱包同样是热钱包。
- **收款钱包地址不对外披露**：由项目方在部署前提供，填入部署 config；公开材料只说明"由项目方热钱包持有"，具体地址至少向审计方/交易所披露（见 docs/10 §9）。
- **管理员 = RoundController 单密钥 owner**，**仅**保留最小权限：开轮、关报名、暂停/恢复预言机、必要时触发结算；不得修改已开轮的目标价 / K 线阈值 / 预言机配置，不得转移用户质押本金。
- **RoundController 不可升级**（D-24 已确认，无升级代理），管理员无法通过升级改变规则。
- 风险接受：单私钥丢失 / 泄露即失去对应资金或管理员能力；缓解要求见 docs/10 §9（硬件钱包、冷热分离、私钥备份、至少向审计/交易所披露、密钥轮换演练）。

### 2.7 销毁口径（V4：三笔）

失败轮次销毁量：

``` text
burnAmount = ROUND_REWARD（7 亿）+ TEAM_ROUND（1.2 亿）+ totalAcceptedStake
```

示例（演示 R2）：700,000,000 + 120,000,000 + 241,500,000 = **1,061,500,000 A9**。
burn_ledger 按三笔记录：kind = `reward` / `team` / `principal`，各自唯一 burnId 与确认状态。团队这一笔由 TeamVault 执行（见 §2.5）。

### 7.1 问题

第 4 轮 72 小时报名期内，若现价已 ≥ 第 4 轮目标价，则结果基本确定（观察期只要不大跌就通过）：参与者在报名时已经知道会赢，等于**无风险白拿 7 亿奖励**，奖励被逐轮抛售，机制失效。

### 7.2 方案 A（备选，不推荐：会破坏「失败不回滚」）：目标价改为相对翻倍

- 每轮**报名截止时锁定**目标价：`targetPrice = 2 × 报名期参考 TWAP`。
- 参考窗口建议取**最后 24 小时**（覆盖率/来源数阈值另定）。
- 连赢 10 轮仍是 **1024 倍**，每轮翻倍语义不变；价格提前超过旧阶梯也不会白拿，因为目标价随之上移。
- `P0 × 2^n` 退化为**早期轮次的参考**，不再作为全程固定目标。
- 待定参数：参考 TWAP 窗口长度、覆盖率与来源阈值、锁定后是否允许变更、报名期数据不足时的回退规则。

### 7.3 方案 B+（**V6 已被取代/取消**，仅存档）：报名窗口与价格联动

> **V6 定案**：95% 闸门与 7 天提档**已取消**；改为开窗时锁定 `max(阶梯, 2×24h TWAP)` + 触价提前关窗。本节仅保留历史决策过程。

核心：**固定阶梯 `P0 × 2^n` 不变**，但报名窗口与价格联动，消除「报名期内价格已达标 → 无风险白拿」。

1. **结算后 24h 缓冲**（公告 / 领奖 / 流动性调整），然后进入下一轮。
2. **开窗价格闸门**：只有现价（**1h TWAP**）≤ 目标价 × **95%** 才开放报名；否则每 4h 检查一次，最长等待 **7 天**。若 7 天仍高于 95%，自动把本轮目标价**提档到下一阶**（`P0 × 2^(n+1)`）再检查（**保持 10 轮与奖励预算不变，只提目标**）。
3. **触价提前关窗**：报名期内若 1h TWAP ≥ 目标价，**立即关闭报名**（不等 72h），并在**下一个 UTC 4 小时边界**开始 72h 观察。目的：价格达标后不再继续收人，断绝无风险参与。
4. **报名窗口上限 72h**（到点正常关闭）；观察窗口**始终 72h / 18 根**，不因提前关窗缩短。
5. **闸门需要可信价格**：测试网手动提交（白名单）、主网必须预言机。
6. 这样「解锁」与「质押」不再冲突：解锁只发生在观察结束后；报名期一旦价格达标即关门。

### 7.4 方案 B（原方案，已被 B+ 取代，仅存档）

- 仅当**现价低于目标价的 95%** 才开报名；否则等待（最长 7 天）；超时则**顺延到下一阶**（跳过本轮，不销毁）。
- 缺点：可能长期空转；状态机更复杂（新增等待态/跳过态）；95% 阈值本身也可能被操纵。B+ 在此基础上补充了 24h 缓冲与「触价提前关窗」，为避免白拿的关键。

### 7.5 方案 C：保留固定阶梯 + 缩短窗口 + 随机截止

- 报名窗口缩到 24~48h，截止时间随机化，配合 commit-reveal 降低狙击。
- 只能**缓解**、不能根治：若价格已明显高于目标价，短窗口仍然白拿。

### 7.6 四个方案的共同前提

- **价格输入必须可信**：测试网为手动提交（白名单、仅测试）；主网必须接入预言机/签名数据源，否则方案 A 的参考价、方案 B+ 的闸门与触价关窗都失去意义。
- 任一方案都会影响 `RoundData.targetPriceUsdE8` 的计算时点、K 线判定语义、前端倒计时与文案；选定后需同步修改 docs/01、02、04、09、11 与合约参数。

### 7.7 当前结论

- **方案 B+ 是 Lead 推荐**：在**保留「固定阶梯、失败不回滚」**的前提下，它是**唯一能根治**「报名期价格达标 → 无风险白拿」的方式。
- 方案 A 会让目标价随报名期 TWAP 变动，**破坏「失败不回滚」规则**（失败轮无法保持原阶梯），故不推荐。
- 方案 C 只能缓解、不能根治。
- 等待项目方在 **A / B+ / C** 中选择（D-26）；选定后再改合约设计与参数。当前配置 `targetMode = FIXED_LADDER`（`RELATIVE_DOUBLE` 仅作为预留开关，未启用）。

### 7.8 D-27 开轮节奏 / 是否手动开轮 / 倒计时传播（**V6 已确认**）

> **V6 定案**：**结算 → 24h 预告期（PREVIEW）→ 自动开窗**；不设常规手动开轮；**取消价格闸门**；前端三个倒计时（距下一轮质押开始 / 距质押结束 / 距判定）。原「仅 R1 手动 / 管理员延后」细节未纳入 V6，正式口径以本节开头为准。

> **状态：待项目方确认，尚未定案。** 以下为 Lead 建议方案，确认后才写入参数与状态机；未定案前**不实现**，当前仍为「结算后立即开轮」。

**背景**：项目方担心**结算后立即开轮、没有预热**，参与人数不足会直接导致销毁，影响很大。

**建议方案**：

1. **不设常规「手动开轮」**：管理员若能在看到价格后择时开轮，会构成中心化质疑，且与 D-24「不可升级 + 最小权限」矛盾。
2. **固定节奏 + 可验证倒计时**：
   - **T0 结算** → 立即公布下一轮参数（目标价、开窗条件、倒计时）；
   - **T0+24h 固定「预告期」（PREVIEW）**：前端显示倒计时 + 分享卡片（X / Telegram），用于传播拉新；
   - 预告期结束**自动**做价格闸门检查（≤ 目标价 × 95%）：满足 → **自动开窗**；不满足 → 页面显示「等待价格回落至 X 以下」状态，每 4h 更新，最长 7 天，超时按 B+ 提档（P0×2^(n+1)）；
   - 开窗后报名最长 **72h**，触价可提前关窗；观察 **48h**；
   - **单轮 ≤6 天，10 轮 ≤60 天**，可提前排期 10 轮公告。
3. **仅 Round 1（TGE 上线首轮）允许管理员手动开轮**（配合上线公告与流动性就绪）；**Round 2~10 全自动**。
4. 管理员**仅保留「延后开轮」权限**：只能延后、不能提前；单次 ≤24h、累计 ≤6 天；且必须在链上写公告事件（可审计）；**不得跳过轮次或改目标价**。
5. **倒计时的终点必须是链上可验证时间**（结算时间 + 24h），不能由管理员随意延长，否则又变成择时操纵。

**与其他决策的关系**：

- 与 **D-26（B+）** 绑定：若 D-26 选 B+，则 PREVIEW + 闸门为可选阶段（状态机见 docs/02 §1 / §4.1）；若选 A 或 C，开轮节奏仍需单独确认。
- 与 **D-24** 一致：管理员权限不扩大（唯一新增的是「延后开轮」，且链上可审计、有上限）。
- **V6 已确认**：结算 → **24h PREVIEW** → 自动开窗；不再有价格闸门/7 天提档. 前端必须提供三个倒计时。
- 原「仅 Round 1 手动开轮 / 管理员延后」细节未在 V6 明确，**不写入正式口径**（如需要另行确认）。

### 7.9 D-28 失败后目标价：同档重试（**V6.1 已确认**）

> **状态：✅ V6.1 已确认。** 对应 docs/12 P0-5。

- **规则**：本轮失败 → 下一轮沿用**同一目标价**；只有本轮**成功**才升到下一档 `P0 × 2^(tier+1)`。
- **例**：R3 目标 $0.008 失败 → R4 目标仍是 **$0.008**，不是 $0.016。
- **影响**：
  - 10 轮**不再等于 10 个档位**（失败会占用轮次）；需要新增「**档位（tier）**」概念：`tier = 1 + 已成功轮数`。
  - 前端阶梯要从「轮次」改为「档位」展示（docs/09 §7 / docs/12 P2）。
  - 价格阶梯表（docs/01 §3）不再是「轮次 n → 2^n」，而是「档位 t → 2^t」。
- **V6.1 定稿**：失败轮不升档，下一轮沿用同一 tier（同档重试）；成功才 `tier += 1`；前端阶梯按「档位」展示；10 轮不再等于 10 个档位。

### 7.13 流动性、内盘销售与撤回规则（V5.6：内盘规则已确认；流动性节奏仍待确认）
