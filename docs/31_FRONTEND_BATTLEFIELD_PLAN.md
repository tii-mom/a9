# 31 — A9 前端深度优化：审计与改造方案（战场化）

**状态：草案，待确认。** 本文只记录审计与方案，未改动任何代码，未 commit。
**基线：** 分支 `claude/practical-rosalind-0da02e`，HEAD `7d0495b`。
**线上观察：** https://a9.lat（2026-11-06，演示数据模式）。
**目标：** 把 A9 从「规则展示站」做成「实时交易战场」——用户进来第一眼就看到战况，并能立即参与。

---

## 0. 结论先行

1. **现在是「资料站 + 一个小游戏模型」，还不是战场。** 首屏一半是叙事文案，实时战况在首屏之下。
2. **品牌不统一。** logo 源文件是 `#FF4D00` 橙底 + 白色开放三角；站内 header 仍是自绘折线图标（`#FF5B1F` + `#FFB63D`）；设计令牌里没有 `#FF4D00`；`--ember: #FFB63D` 琥珀色与品牌橙抢视觉。
3. **实时性是「多接口轮询 + 每秒整页重渲染」，不是推送。** 隐藏标签页也不会停止轮询。
4. **首页的核心交易没有接通链上。** 真钱包下质押只弹出「合约待接入」，领取走演示 API。真实 TON 链路只在 `/me` 页面。
5. **信任风险。** 连接失败会降级为演示钱包（假余额）；生产环境常驻「原型 · 模拟数据」徽标；线上观察到倒计时显示 `00:00:00` 而状态仍是「报名中」（待复现）。

## 1. 业务核心（前端要服务的东西）

**一句话：** 用户押本金，赌 72 小时内 TWAP 价格至少翻倍。目标价在观察窗口开窗时锁定；判定规则为 24 根 1 小时 K 线中，至少 16 根 TWAP ≥ 目标价。赢：本金退还，7 亿奖励按质押占比认领；输：奖励与本轮全部质押本金销毁。共 10 轮，失败不升档（D-28）。

**依据：** `README.md` 顶部 V7 段；第 37–39 行（V6.1 / V6.2 追加段）；第 106 行（质押上下限）；第 169–171 行（经济与法务风险条目）。

**一轮的生命周期：** 结算 → 12h 预告 → 报名质押 → 关窗（触价可提前关窗）→ 观察 24h → 判定 → 认领。
报名窗口口径存在历史差异：V5/V6 段为 72h，V7 起为 36h。站内文案目前写 36h，**需产品复核**。

**前端必须真实表达的五件事：**

| # | 信息 | 口径要点 |
|---|---|---|
| 1 | 目标价 | `max(P0×2^tier, 2×开窗时 24h TWAP)`，开窗锁定，tier = 1 + 已成功轮数 |
| 2 | 判定进度 | 24 根里点亮几根，需要几根，最多容错几根 |
| 3 | 三类倒计时 | 距下一轮报名 / 距报名截止 / 距判定 |
| 4 | 池子与仓位 | 本轮质押池、我的质押、占池比例、预计奖励 |
| 5 | 本金与奖励去向 | 通过：退还 + 认领；失败：奖励与本金销毁 |

另外，风险披露必须显著：**本金可能全部归零**（README 第 171 行，D-34 要求的「高风险、可能损失全部本金」）。

## 3. 视觉语言：从「FUSE 暗色工控台」到「A9 橙色战场」

### 3.1 方向

暖黑底 + 单一品牌橙 + 白色三角（logo）。橙色只用于四件事：**品牌、主 CTA、目标线（战斗目标）、焦点状态**。

### 3.2 色板（提案，待确认）

| Token | 值 | 用途 / 说明 |
|---|---|---|
| `--brand` | `#FF4D00` | logo、主 CTA、目标线 |
| `--brand-hi` | `#FF7A3D` | hover、发光（on dark ≈ 7.7:1） |
| `--ink-on-brand` | `#0A0807` | 橙底上的文字（≈ 6.0:1） |
| `--bg` / `--panel` / `--line` | `#0A0807` / `#14100D` / `#2B241D` | 沿用 |
| `--text` / `--text-2` / `--muted` | `#F0E8D9` / `#BDB19B` / `#9A8F7D` | 沿用 |
| `--up` | `#3DDC97` | 涨、通过 |
| `--down` | `#E5484D`（约 4.8:1 on panel，需色盲模拟验证） | 跌、失败；与品牌橙拉开色相 |
| `--warn` | 建议偏黄 `#FFC933` | 观察中、时间紧张；替代现在的琥珀 |

**阶段颜色映射：** 报名 = 橙（可以参战）；观察 = 黄（张力，时间在走）；通过 = 绿；失败 = 红；未开启 = 灰。

**按钮按下态：** 用位移 + 内阴影，不用更深的橙底（深橙配黑字对比会掉到约 3.7:1）。

### 3.3 Logo 落地

- 源文件：`~/Downloads/a9-logo/01_square/logo_square.svg`（方形满版，用于 header、favicon、App 图标）。
- `~/Downloads/a9-logo/02_circle/` 的圆形徽章用于头像、社交卡片。
- header 改用官方 SVG；最小显示尺寸 16px；不改色、不描边、不加效果。

### 3.4 字体

- Big Shoulders（数字）、IBM Plex Mono（数据）、Noto Sans SC（正文）保留。
- 中文字重从 4 个减为 2 个（500、900）。
- 子集化自托管，或至少改为非阻塞加载。

### 3.5 动效语言

- 价格 tick：闪色 ≤ 300ms，不产生位移。
- K 线收盘点亮：「引信」扫过一次（这是 FUSE 隐喻的核心，应保留并放大）。
- 目标价被穿越：一次性提示，不循环。
- 结算页克制，不做赌场式烟花。
- 减弱动效时：保留状态变化，只去掉扫光与循环闪烁。

```

│ 顶栏：logo · 状态 · 钱包                                      │
├───────────────────────────────────────┬──────────────────────┤
```

### 4.3 移动端首屏

- 首屏只有：阶段、倒计时、现价 vs 目标、点亮条。
- 底部只保留一条操作坞（主 CTA + 次 CTA）。
- 钱包入口进 header，去掉浮动「连接钱包」按钮。
- Hero 文案收进折叠。

### 4.4 状态设计

- 加载：骨架屏，按真实布局占位，不显示「--」。
- 空态：报名中但 0 人参战，显示「第一位参战者」之类的引导，而不是「0 / 0」。
- 数据龄：「3 秒前更新」。
- 数据延迟：横幅提示。
- 演示模式：全局可见标识；生产环境关闭。

### 4.5 参与感（必须真实）

- **战况事件流：** 只显示真实事件（有人质押、第 N 根 K 线点亮、价格上穿或跌破目标、判定结果），地址缩写。
- **我的仓位卡：** 本金、占池比例、奖励计算公式、距判定时间、可分享海报（不含收益率承诺）。
- **阶梯攀登：** 当前档位与已成功轮数高亮；同档重试需明确标注。
- **沙盘推演：** 保留，移到规则页。

### 4.6 文案

- H1 按 README「文案纪律」保留，不改。
- 顶部 tape 的「10 轮目标价逐轮翻倍」与 D-28（失败不升档）冲突，建议改为「成功才升档」的口径。**待产品确认。**

## 5. 实时性

### 5.1 现状问题

- 7 个请求，间隔 2–5s。
- 1s 时钟让整页每秒重渲染。
- 隐藏页仍在轮询。
- 倒计时用客户端 `Date.now()` 计算，用户时钟偏差会直接显示错误时间。

### 5.2 目标指标（提案）

| 指标 | 目标 |
|---|---|
| 价格从服务器到屏幕 | ≤ 1s（P95） |
| 隐藏标签页的网络请求 | 0 |
| 每秒重渲染的组件 | 仅时钟与价格两个叶子组件 |
| 移动端首屏 LCP | ≤ 2.5s（4G，实测） |
| INP | ≤ 200ms |
| 首屏 JS 体积 | 基线测量后定预算 |

### 5.3 A 步：纯前端，无需后端

1. 时钟下沉到叶子组件。
2. 数据层合并为单一 snapshot store（`useSyncExternalStore`）。
3. 可见性门控真正生效（隐藏即停，可见即补一次）。
4. 价格与成交组件加 `memo`。
5. 服务器时间偏移校准。需要后端在响应中给出服务器时间，若无则新增字段（需后端配合）。

### 5.4 B 步：推送（需后端 worker）

- SSE 或 WebSocket（Durable Object 做 fan-out）推送 tick、成交、轮次事件。
- 带 `seq` 的断线补齐。
- 心跳。
- 失败回退到 A 步轮询。

## 6. 链上接入：把演示变成真

### 6.1 现状

首页两条路径并存：
- 演示 API：质押、领取、买入。
- TON 链路：仅在 `/me`（`ChainMePanel`、`RefundClaimPanel`）。

### 6.2 目标

一个 `BattleService` 接口（`getSnapshot` / `stake` / `claim` / `buyPreview`），提供 demo 与 chain 两个实现。组件内部不写 `if (demo)`，由 `config.dataSource` 与钱包模式在服务层决定。

### 6.3 交易体验

- 风险确认分两步：「本金可能归零」与「失败时销毁」各需显式确认。`acceptFullPrincipalBurn` 不再硬编码。
- 交易状态机：待签名 → 已广播 → 链上确认 → 成功 / 失败，附浏览器链接。
- 金额预校验：单笔最低 10,000 A9；单地址不超过 20,000,000 A9；本轮剩余额度。
- 窗口关闭前提交失败，给出专门提示。

### 6.4 钱包

- 生产构建关闭演示钱包。
- 连接失败不得静默降级为演示余额。
- 演示余额只在 demo 模式显示，且全程标注。

### 6.5 依赖

需确认链上读取能否直接提供前端所需的轮次、池子、仓位数据：toncenter / tonapi，或 worker 的 indexer 输出（`docs/20`）。

## 8. 风险与合规边界

**文档事实（需前端守住）：**
- 2× 通过率约 0.15%–1.64%，上限池 EV 约 −89% 至 −98%（`README.md` 第 169 行，`docs/13`）。
- V6.2 写明项目接受「靠 FOMO 驱动」（`README.md` 第 39 行）。
- D-34：项目不出具正式法律意见。

**设计红线（建议写入团队规范）：**
1. 不做假数据、假人数、假成交。演示数据明确标注，生产关闭。
2. 倒计时只陈述事实（剩余时间、还需几根），不用「最后机会」「即将售罄」之类话术。
3. 不展示收益率诱导；奖励只展示计算公式与本金去向。EV 与通过率数据在规则页公开（引用 `docs/13`）。
4. 风险确认不默认勾选，分两步确认；风险横幅在操作坞旁常驻。
5. 以下事项上线前需法务确认：地域与年龄限制；邀请加成（V8 referral）与连续参与加成是否构成推广或返佣问题。

**我的立场：** 战场感可以做到顶级，但不做诱导性紧迫感，也不做虚假社交证明。建议上线前至少做一次合规审查。这是建议，不替代法律意见。

**本轮修复的问题（按发现顺序）**
1. 首屏布局位移（CLS）：数据到达后战场高度变化，把下方内容推走。固定为实测的最终高度（按断点），并给「报名/观察」两种状态都预留移动端操作区高度。

3. 首屏 LCP 变差：盘面数据是首屏最大元素，需要两次串行请求后才出现，LCP 从 2.1 s 退到 4.8 s（单次结果，之后复现为 5.6 s）。在盘面上方加入一行静态论点（与 Hero 标题同文案），让首帧即有文字型 LCP 候选，LCP 回到 2.1 s。
